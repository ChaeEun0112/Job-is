# 데이터 처리 방식

### MVP 데이터 처리 원칙


> ### 1️⃣ 사용자 입력 데이터  
>   
> 사용자의 기본 프로필 및 관심 정보를 기반으로 추천 데이터를 구성한다.  
>   
> ### 수집 데이터  
>   
> - 관심 직무  
>   
> - 희망 지역  
>   
> - 경력 및 기술 스택  
>   
> - 선호 조건  
>   
> - 사전 등록 정보


> ### 2️⃣ 추천 후보 데이터  
>   
> 사용자에게 제공할 추천 데이터는 다양한 취업 관련 정보를 통합하여 구성한다.  
>   
> ### 추천 데이터 범위  
>   
> - 채용 공고  
>   
> - 커리어 뉴스  
>   
> - 청년 혜택 및 지원 정보


> ### 3️⃣ 행동 데이터 수집  
>   
> 사용자의 실제 반응 데이터를 기반으로 추천 품질을 개선한다.  
>   
> ### 행동 데이터 항목  
>   
> - 이메일 오픈  
>   
> - 클릭  
>   
> - 저장  
>   
> - 스킵  
>   
> - 지원  
>   
> - 사용자 피드백


> ### 4️⃣ 추천 처리 방식  
>   
> 초기 MVP 단계에서는 규칙 기반 추천과 수동 큐레이션 방식을 혼합하여 운영할 수 있다.  
>   
> ### 추천 처리 방향  
>   
> - 초기: Rule-based + 수동 큐레이션 혼합  
>   
> - 이후: 행동 데이터 기반 자동화 추천 고도화  
>   
> - 자동화 수준 및 AI 적용 범위는 PRD 단계에서 확정 예정


> ### 5️⃣ 추천 개선 루프  
>   
> 사용자의 행동 데이터를 다음 추천 과정에 반영하여 추천 정확도를 지속적으로 개선한다.  
>   
> ### 개선 방식  
>   
> - 관심도가 높은 항목 우선 노출  
>   
> - 부적합 조건 제거  
>   
> - 사용자 반응 기반 추천 우선순위 조정  
>   
> - 사용할수록 정교해지는 개인화 추천 구조


> ### 6️⃣ 분석 및 성과 측정 데이터  
>   
> 추천 품질과 사용자 반응을 확인할 수 있도록 이벤트 기반 데이터 구조를 설계한다.  
>   
> ### 주요 분석 지표  
>   
> - Activation  
>   
> - 추천 품질  
>   
> - 채널별 성과  
>   
> - 첫 행동 발생 여부

### 핵심 방향


Job.is는 사용자의 행동 데이터를 기반으로 추천 품질을 지속적으로 개선하며, 
단순 정보 제공이 아닌 “사용할수록 더 정교해지는 개인 맞춤형 취업 큐레이션 시스템”을 목표로 한다.


입력 데이터, 추천 후보 데이터, 행동 데이터, 추천 처리, 개선 루프, 분석 데이터를 분리해 정의한다. 


결정 필요) 실제 외부 데이터 소스, 개인정보 저장 기준, 자동화 수준

## 입력 데이터


입력 데이터는 개인화 추천의 초기 조건이다. MVP에서는 최소 입력으로 첫 추천 품질을 만들고, 이후 행동으로 보완하는 방향이 적합하다.


| 데이터     | 목적          | 예시 필드                   | 메모                   |
| ------- | ----------- | ----------------------- | -------------------- |
| 사용자 프로필 | 기본 추천 조건 설정 | 관심 직무, 지역, 경력 단계, 기술 스택 | 세그먼트 정의는 아직 확정 전     |
| 선호 조건   | 부적합 추천 제거   | 희망 조건, 선호 업무, 제외 조건     | 입력 부담을 낮춰야 함         |
| 피드백 선호  | 다음 추천 조정    | 관심 없음, 더 보고 싶음, 저장      | 세부 이벤트명은 PRD에서 정의 필요 |

## 추천 후보 데이터


추천 후보 데이터는 채용 공고만으로 제한하지 않는다. 현재 합의는 공고, 커리어 뉴스, 청년 혜택 및 지원 정보를 함께 다루는 취업비서다.


| 후보 유형         | 경험 내 역할          | MVP 처리   | 열린 쟁점        |
| ------------- | ---------------- | -------- | ------------ |
| 채용 공고         | 가장 직접적인 취업 행동 후보 | 우선 추천 후보 | 실제 데이터 소스 미정 |
| 커리어 뉴스        | 판단 맥락과 직무 이해 보완  | 보조 추천 후보 | 수집 방식 미정     |
| 청년 혜택 및 지원 정보 | 취업 준비 흐름의 보완 정보  | 보조 추천 후보 | 갱신 주기 미정     |


[DB 설계](https://app.notion.com/p/3652e0416c208054b1c5c33883b66a46) 


외부 데이터 소스는 아직 확정하지 않는다. 
공공 API, 크롤링, 회사 페이지, 수동 수집, RAG 또는 LLM 사용 범위는 미결.

## 행동 데이터


행동 데이터는 Activation 판단과 추천 개선의 공통 기반이다. 단순 조회보다 추천을 본 뒤 어떤 판단을 남겼는지에 초점을 둔다.


| 행동                    | 용도                       | 연결 지표             | 상태        |
| --------------------- | ------------------------ | ----------------- | --------- |
| Open                  | 추천 전달 경험 소비 여부 확인        | 첫 오픈율             | To define |
| Click                 | 관심 항목 탐색 여부 확인           | 첫 추천 클릭률, 항목별 클릭률 | To define |
| Save                  | 적합 또는 나중에 볼 가치가 있는 항목 확인 | 저장 비율, 저장 대비 스킵   | To define |
| Skip                  | 부적합 추천 제거 신호 확보          | 스킵 비율, 부적합 사유     | To define |
| Apply or apply intent | 취업 행동 연결 가능성 확인          | 첫 지원 또는 지원 의향     | To define |
| Feedback              | 추천 개선 사유 확인              | 부적합 사유 분포         | To define |

## 추천 처리


초기 MVP는 완전 자동 추천 시스템을 전제로 하지 않는다. 
현재 단계에서 확정하는 것은 사용자의 조건과 행동 신호를 추천 우선순위에 반영해야 한다는 원칙이다.


| 처리 계층         | MVP 방향                          | 경계              |
| ------------- | ------------------------------- | --------------- |
| 적합성 필터링       | 직무, 지역, 조건 기준으로 명백히 맞지 않는 항목 제외 | 세부 규칙은 미정       |
| 수동 큐레이션       | 초기 품질 확보를 위해 사람이 후보를 선별할 수 있음   | 운영 비용과 범위 미정    |
| 규칙 기반 랭킹      | 프로필 조건과 행동 신호로 우선순위 조정 가능       | 알고리즘 확정 아님      |
| RAG 또는 LLM 지원 | 추천 이유 생성 또는 후보 요약에 사용           | 적용 범위 미정        |
| 완전 자동화        | 장기 방향 후보                        | MVP 범위로 확정하지 않음 |

## 개선 루프


추천 개선 루프는 Job.is의 차별화 가설이다. 정적 AI 레터가 아니라, 
사용자가 열고, 저장하고, 스킵하고, 클릭하고, 지원할수록 다음 추천이 나아진다는 경험을 설계해야 한다.

1. 사용자가 프로필과 관심 조건을 입력한다.
2. 시스템 또는 운영자가 소수 추천 후보를 구성한다.
3. 사용자가 아침 추천을 열고 항목별 행동을 남긴다.
4. 저장, 스킵, 클릭, 지원 의향, 부적합 사유를 다음 추천 조건에 반영한다.
5. 다음 추천에서 더 맞는 항목의 우선순위를 높이고, 부적합 조건을 줄인다.
