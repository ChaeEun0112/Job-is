# Job.is - Product Requirements Document

## 1. 서비스 목적

Job.is는 매일 새로 올라오는 채용 공고 중 사용자에게 맞는 공고를 선별해 아침마다
"레터" 형태로 전달하는 맞춤 취업 뉴스레터 서비스입니다. 사용자는 추천 공고를 빠르게
검토하고, 관심 있는 공고는 저장하거나 지원 의향을 표시할 수 있습니다. 필요할 때는 조건을
지정해 공고를 직접 탐색합니다.

## 2. 문제 정의

- 채용 공고가 매일 대량으로 올라와서 관련 있는 공고만 골라내기 어렵습니다.
- 공고 하나하나가 내 조건(직무/지역/경력/기술스택)과 얼마나 맞는지 판단하는 데 시간이 듭니다.
- 성향이나 적성을 기준으로 한 추천 근거 없이 키워드 검색만으로는 "왜 이 공고가 나에게
  맞는지" 알기 어렵습니다.
- 관심 공고와 이미 확인한 공고를 분리해 관리하기 어렵습니다.

## 3. 타겟 사용자

### 3.1 주요 사용자

- 매일 아침 정리된 채용 정보를 받아보고 싶은 구직자
- 조건 기반 필터링(직무/지역/경력/고용형태)으로 직접 공고를 찾고 싶은 구직자
- 자신의 적성, 경력, 선호 조건을 반영한 추천 근거가 필요한 구직자

### 3.2 사용자 니즈

- 온보딩에서 입력한 프로필과 적성 결과를 바탕으로 맞춤 공고를 추천받는다.
- 추천 공고의 적합도와 추천 이유를 보고 저장, 관심없음, 지원 여부를 판단한다.
- 저장한 공고와 열람·피드백 이력을 한곳에서 다시 확인한다.
- 프로필·서류·알림 설정을 필요할 때 수정한다.

## 5. 핵심 기능

### F-01: 인증 및 온보딩

#### 목표

사용자가 소셜 로그인 후 필수 약관에 동의하고, 개인화 추천에 필요한 프로필·서류·적성 정보를
완료하도록 합니다.

#### 로그인 및 진입 흐름

1. 비로그인 사용자가 보호된 화면에 접근하면 로그인 화면으로 이동합니다.
2. 사용자는 Google 또는 Kakao 계정으로 로그인합니다.
3. 로그인에 성공한 기존 사용자는 온보딩 완료 여부에 따라 오늘의 추천 또는 온보딩으로 이동합니다.
4. 신규 사용자는 약관 동의 후 온보딩을 시작합니다.
5. 로그인 실패 또는 이메일 확인이 필요한 경우, 원인을 안내하고 다시 로그인할 수 있어야 합니다.

#### 온보딩 흐름

| 단계 | 화면            | 사용자 작업                                                  | 완료 결과                                      |
| ---- | --------------- | ------------------------------------------------------------ | ---------------------------------------------- |
| 1    | 프로필 기본정보 | 관심 직무, 희망 지역, 경력, 선호·제외 조건, 기술 스택을 입력 | 입력 내용을 임시 저장하고 다음 단계로 이동     |
| 2    | 서류 업로드     | 이력서 또는 자기소개서 파일을 업로드·삭제                    | 업로드한 서류 목록을 확인하고 다음 단계로 이동 |
| 3    | 적성 퀴즈       | 문항별 선택지를 고르고 결과를 확인                           | 결과를 프로필에 적용하고 온보딩 완료           |

- 단계 중 이탈해도 임시 저장된 정보와 이미 답한 퀴즈 문항을 바탕으로 이어서 진행할 수 있어야 합니다.
- 온보딩 완료 후 사용자는 오늘의 추천 화면으로 이동합니다.
- 프로필 또는 서류 저장에 실패하면 현재 입력을 유지하고 재시도 방법을 안내합니다.

### F-02: 오늘의 추천

#### 목표

사용자가 그날의 개인화 추천 공고를 레터 덱으로 확인하고, 공고별 의사를 빠르게 남기도록 합니다.

#### 브리핑 상태

| 상태           | 사용자에게 제공하는 화면 및 행동                                  |
| -------------- | ----------------------------------------------------------------- |
| 온보딩 미완료  | 추천을 받기 위해 온보딩을 완료하도록 안내                         |
| 발송 전        | 아직 오늘의 추천이 준비되지 않았음을 안내                         |
| 추천 후보 없음 | 조건에 맞는 공고가 없음을 안내하고 탐색 또는 프로필 보완으로 연결 |
| 추천 준비 완료 | 인사말, 추천 건수, 테마를 보여주고 레터 덱으로 진입               |

#### 레터 덱

- 공고 카드에는 공고명, 직무 범위, 회사 위치, 기술 스택, 마감 정보, 적합도, 추천 이유와 요약을 표시합니다.
- 사용자는 카드에서 공고를 저장하거나 관심없음으로 처리할 수 있습니다.
- 관심없음 처리 후에는 사유와 추가 의견을 남길 수 있으며, 취소할 수 있어야 합니다.
- 덱의 모든 공고를 확인하면 완료 화면을 보여주고, 추천 콘텐츠 또는 지난 레터로 이동할 수 있어야 합니다.
- 추천 공고를 선택하면 공고 상세 화면으로 이동합니다.

#### 추천 콘텐츠와 아카이브

- 사용자는 뉴스·혜택 콘텐츠의 목록과 상세를 확인하고 원문으로 이동할 수 있습니다.
- 사용자는 지난 추천 레터를 아카이브에서 다시 확인할 수 있습니다.
- 콘텐츠 또는 추천 데이터를 불러오지 못하면 재시도할 수 있는 오류 상태를 표시합니다.

### F-03: 공고 탐색

#### 목표

추천 외에 사용자가 원하는 조건으로 공고를 직접 찾도록 합니다.

#### 검색 및 필터

- 사용자는 키워드로 공고를 검색할 수 있습니다.
- 직무, 지역, 경력, 고용형태, 원격 근무, 상시 채용 여부와 정렬 기준을 조합해 결과를 좁힐 수 있습니다.
- 필터 또는 정렬이 바뀌면 첫 결과 페이지부터 다시 조회합니다.
- 선택한 조건은 활성 필터로 표시하며, 개별 삭제 또는 전체 초기화가 가능해야 합니다.

#### 결과 상태와 이동

- 결과가 있으면 공고 목록, 전체 결과 수, 페이지 이동 수단을 표시합니다.
- 결과가 없으면 조건을 조정하거나 초기화할 수 있도록 안내합니다.
- 조회 중에는 로딩 상태를, 조회 실패 시에는 재시도 수단을 제공합니다.
- 공고 카드를 선택하면 공고 상세로 이동하고, 목록 또는 상세에서 저장 상태를 변경할 수 있습니다.

### F-04: 저장 목록 및 활동 히스토리

#### 목표

사용자가 관심 공고와 자신의 확인·피드백 이력을 다시 찾아 다음 행동을 결정하도록 합니다.

#### 저장 목록

- 저장한 공고를 저장일 또는 마감 임박 순으로 조회합니다.
- 저장 건수와 지원 의향 건수를 함께 보여줍니다.
- 각 공고에서 회사, 직무, 위치, 경력·고용 조건, 저장일, 마감 상태, 지원 의향 상태를 확인할 수 있습니다.
- 사용자는 저장을 해제하거나 상세 화면으로 이동할 수 있습니다.
- 마감된 공고는 저장 목록에서 구분하고, 지원 동작을 제한합니다.

#### 열람·피드백 이력

- 사용자는 전체, 열람, 관심없음, 지원 의향 상태로 이력을 필터링합니다.
- 이력은 발생 날짜별로 묶어 보여주며, 추가 이력이 있으면 더 불러올 수 있습니다.
- 각 이력에서 관련 공고 상세로 다시 이동할 수 있습니다.
- 빈 목록, 로딩, 오류 상태에는 각각의 안내와 재시도 수단을 제공합니다.

### F-05: 프로필 및 적성 정보 관리

#### 목표

사용자가 추천 기준이 되는 정보를 언제든 수정하고, 필요할 때 적성 결과를 다시 확인하도록 합니다.

- 사용자는 관심 직무, 희망 지역, 경력 단계, 선호·제외 조건, 기술 스택과 자기소개 정보를 수정할 수 있습니다.
- 사용자는 이력서와 자기소개서 파일을 업로드·삭제하고 업로드된 파일 목록을 확인할 수 있습니다.
- 사용자는 적성 퀴즈를 다시 응시하고, 결과를 프로필에 적용할 수 있습니다.
- 저장 또는 업로드에 실패한 경우 현재 화면에서 원인을 안내하고 재시도할 수 있어야 합니다.

### F-06: 알림, 계정 및 수신 설정

#### 알림 설정

- 사용자는 오늘의 브리핑 수신 여부, 수신 시간대, 마케팅 정보 수신 동의를 변경할 수 있습니다.
- 사용자는 알림을 7일, 30일 또는 무기한으로 일시 정지하고 다시 해제할 수 있습니다.
- 변경 결과는 현재 설정 화면에 즉시 반영되어야 합니다.

#### 계정 관리

- 사용자는 가입한 소셜 계정 정보와 수신 이메일을 확인할 수 있습니다.
- 사용자는 탈퇴 사유를 선택하거나 직접 입력해 회원 탈퇴를 요청할 수 있습니다.
- 탈퇴 후 복구 가능한 기간을 안내하고, 기간 내 재로그인한 사용자는 계정을 복구할 수 있어야 합니다.

#### 이메일 수신거부

- 사용자는 이메일 링크를 통해 로그인 없이 수신을 거부하거나 다시 구독할 수 있습니다.
- 수신거부 이유를 선택하고 추가 의견을 남길 수 있습니다.
- 이메일 링크에 유효한 식별 정보가 없거나 처리에 실패하면, 상태를 안내하고 설정 화면 또는 고객 지원 경로를 제공합니다.

### F-07: 공고 상세 및 지원 행동

#### 목표

사용자가 공고의 조건과 추천 근거를 검토한 뒤 저장, 지원 의향, 외부 지원으로 이어지도록 합니다.

- 상세 화면에는 회사·직무 정보, 경력·고용 조건, 근무지, 기술 스택, 마감 정보, 업무·자격 요건·우대 사항·복지 정보를 표시합니다.
- 추천을 통해 진입한 경우 적합도와 추천 이유를 함께 확인할 수 있습니다.
- 공고를 열면 열람 이력을 남기고, 사용자는 저장 또는 저장 해제와 지원 의향 토글을 할 수 있습니다.
- 사용자가 지원하기를 선택하면 원문 공고로 이동하기 전 지원 행동을 기록합니다.
- 원문이 만료되었거나 연결할 수 없는 공고는 별도 만료 안내 화면을 보여주고, 탐색 또는 저장 목록으로 돌아갈 수 있게 합니다.

## 6. 공통 규칙 및 상태

### 접근 및 이동

- 로그인하지 않은 사용자가 추천, 탐색, 저장 목록, 프로필, 설정, 공고 상세 등 보호된 화면에
  접근하면 로그인 화면으로 이동합니다.
- 로그인한 사용자가 랜딩 또는 로그인 화면에 접근하면 온보딩 완료 여부에 따라 오늘의 추천 또는
  온보딩으로 이동합니다.
- 설정 기본 경로는 알림 설정 화면으로 연결합니다.
- 존재하지 않는 경로는 404 화면으로 안내합니다.

### 피드백 상태

- 서버 데이터를 조회하는 화면은 로딩 중, 데이터 없음, 오류 상태를 구분해 보여줍니다.
- 오류 상태에서는 사용자가 원래 화면 맥락을 잃지 않고 재시도하거나 이전 화면으로 돌아갈 수 있어야 합니다.
- 저장, 관심없음, 지원 의향, 알림 설정처럼 결과가 바뀌는 행동은 성공 또는 실패를 즉시 안내합니다.
- 파괴적 행동(저장 해제, 회원 탈퇴 등)은 행동의 결과를 이해할 수 있도록 확인 또는 완료 안내를 제공합니다.

### 문서 범위

- 이 문서는 사용자 관점의 기능, 상태, 이동 결과를 정의합니다.
- API 요청 형식과 응답 계약은 API Reference를, 컴포넌트 구조와 구현 규칙은 프로젝트 컨벤션을 따릅니다.
