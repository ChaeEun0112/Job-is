# React Best Practices (job-is-fe 적용판)

React 19 + Vite CSR SPA, TanStack Query, Zustand, react-router 환경에서 새 컴포넌트와 훅을
작성하거나 리뷰할 때 참고하는 성능 가이드입니다.

## 1. 비동기 처리

- **병렬 처리** — 서로 의존하지 않는 비동기 작업은 `Promise.all()`로 묶습니다. 순서대로
  `await`를 나열하면 불필요한 워터폴이 생깁니다.
- **await 지연** — 특정 분기에서만 쓰는 값은 그 분기 안에서 `await`합니다. 함수 최상단에서
  미리 기다리지 않습니다.
- **싼 조건 먼저 확인** — 원격 값이나 플래그를 기다리기 전에, 로컬에서 바로 판단 가능한
  조건(옵션 플래그, 캐시된 값 등)을 먼저 체크해서 불필요한 대기를 피합니다.
- **Suspense 경계** — `React.lazy` + `Suspense`로 무거운 라우트를 나누는 지금 방식
  (`src/routes/lazyComponents.ts`)을 유지합니다. 새 라우트를 추가할 때도 동일하게 적용합니다.

## 2. 번들 사이즈

- **동적 임포트** — 무거운 컴포넌트(차트, 에디터 등)는 `React.lazy`로 분리합니다.
- **서드파티 지연 로드** — 분석/로깅 스크립트는 초기 렌더링이 끝난 뒤(`useEffect`
  이후)에 로드합니다.
- **조건부 로드** — 특정 기능이 실제로 켜졌을 때만 관련 모듈을 import합니다.
- **hover/focus 프리로드** — 다음 화면으로 이동할 가능성이 높은 링크/버튼에서는 hover
  시점에 해당 라우트 청크를 미리 로드해 체감 속도를 높입니다.

## 3. 클라이언트 데이터 페칭

- **전역 이벤트 리스너 중복 방지** — 여러 컴포넌트가 각자 `window.addEventListener`를
  걸지 않도록 공용 훅으로 묶습니다.
- **passive 리스너** — 스크롤/터치 이벤트는 `{ passive: true }`로 등록해 메인 스레드
  블로킹을 줄입니다.
- **localStorage 스키마 버전 관리** — `localStorage`/`sessionStorage`에 저장하는 데이터는
  최소한으로 유지하고, 구조가 바뀔 수 있으면 버전 필드를 둡니다. (`useAuthStore`의
  `sessionStorage` persist, 추천 인트로 애니메이션의 `localStorage` 키 등에 적용됩니다.)

## 4. 리렌더링 최적화

- **파생 상태는 렌더링 중 계산** — `useEffect`로 상태를 동기화하지 말고, 렌더링 중에
  바로 파생시킵니다.
- **함수형 `setState`** — 이전 상태를 참조할 때는 `setState(prev => ...)` 형태를 써서
  콜백을 안정적으로 유지합니다.
- **`useState` 초기값은 함수로** — 비용이 큰 초기값 계산은
  `useState(() => expensiveInit())` 형태로 지연시킵니다.
- **이벤트 로직은 핸들러로** — 사용자 상호작용에서만 필요한 로직을 `useEffect`에 넣지
  말고 이벤트 핸들러 안에 둡니다.
- **컴포넌트 내부에 컴포넌트를 정의하지 않기** — 렌더링마다 새 컴포넌트 타입이 생겨
  매번 언마운트/리마운트됩니다.
- **원시값 의존성 사용** — `useEffect`/`useMemo` 의존성 배열에는 객체 전체보다 원시값을
  넣어서 불필요한 재실행을 줄입니다.
- **파생 boolean 구독** — 원본 값 전체가 아니라 컴포넌트가 실제로 필요로 하는 파생
  boolean만 구독합니다(Zustand selector 작성 시 특히 유효합니다).
- **독립적인 훅은 분리** — 서로 의존성이 다른 로직을 한 커스텀 훅에 몰아넣지 않습니다.
- **간단한 값에는 `useMemo` 남용 금지** — 원시값 연산처럼 메모이제이션 비용이 계산
  비용보다 큰 경우 그냥 계산합니다.
- **비긴급 업데이트는 `useTransition`** — 즉시 반영이 필요 없는 상태 업데이트는
  `startTransition`으로 감싸 입력 반응성을 지킵니다.
- **잦은 값은 ref로** — 렌더링에 반영할 필요 없는 값(예: 스크롤 위치, 드래그 좌표)은
  `useRef`로 관리합니다.

## 5. 렌더링 성능

- **삼항 연산자 우선** — 조건부 렌더링에 `&&`보다 삼항 연산자를 씁니다
  (`0`/`NaN`이 그대로 렌더링되는 실수를 방지).
- **긴 리스트에 `content-visibility`** — 매우 긴 목록(예: 탐색 결과 그리드)에는
  `content-visibility: auto`로 화면 밖 렌더링 비용을 줄이는 것을 검토합니다.
- **정적 JSX는 컴포넌트 밖으로** — 매 렌더링마다 새로 만들 필요 없는 JSX는 컴포넌트
  바깥 상수로 뺍니다.
- **SVG 애니메이션은 wrapper에** — SVG 자체보다 감싸는 `div`에 transform/opacity
  애니메이션을 겁니다.
- **`useTransition`으로 로딩 상태 표시** — 별도 로딩 boolean 대신 `useTransition`의
  `isPending`을 활용할 수 있는지 검토합니다.

## 6. JavaScript 성능

- **조기 반환** — 함수 초반에 예외/기본 케이스를 걸러내고 바로 반환합니다.
- **Map/Set으로 조회** — 반복 조회가 필요하면 배열 `find` 대신 `Map`/`Set`을 만들어
  O(1) 조회로 바꿉니다.
- **반복문 합치기** — 여러 번의 `filter`/`map` 체인을 한 번의 순회로 합칠 수 있는지
  검토합니다(`flatMap` 포함).
- **정규식/함수 결과 캐싱** — 루프 안에서 매번 만드는 `RegExp`나, 같은 입력에 대해
  반복 계산되는 함수 결과는 모듈 스코프에 캐싱합니다.
- **`toSorted()` 사용** — 원본 배열을 변경하지 않아야 할 때 `sort()` 대신
  `toSorted()`를 씁니다.
- **불필요한 idle 작업 지연** — 당장 필요 없는 부수 작업은
  `requestIdleCallback`(또는 유사 스케줄링)으로 미룹니다.

## 7. 고급 패턴

- **이벤트 핸들러는 ref에 저장해 최신값 유지** — `useEffect` 의존성 배열을 늘리지 않고도
  최신 콜백을 참조하고 싶을 때 씁니다.
- **앱 초기화는 한 번만** — 모듈 스코프 플래그 등으로 앱 전체에서 한 번만 실행돼야 하는
  초기화 로직(예: 분석 도구 초기화)을 보장합니다.

  따릅니다. 이 문서와 상충하면 프로젝트 컨벤션이 우선합니다.
